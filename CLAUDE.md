# Diskette Toolkit — notes for Claude

Windows tool for reading, writing, formatting and testing floppies and disk images (Atari ST first, plus PC, MSX,
Mac, Amiga, PCW, MINIX, ext2). Formerly "AtariFloppy" — namespaces, Core/Tests assembly names and resource
LogicalNames still use `AtariFloppy.*` on purpose; don't rename them.

## Language
English is the project's main language on GitHub: README.md, commit messages, issues, release notes.
The program UI follows the Windows language (Czech/Slovak → Czech, otherwise English). Czech users get
`NAVOD.txt` (full guide) and `Mechaniky-CZ.png` in the ZIP; `README.txt` and `Drives-EN.png` are English.

## Owner
Wary (HoroPC) does not program. He decides WHAT, Claude writes all code. Talk to him in Czech, about behaviour he
can see in the program, with exact click paths. He tests on real hardware: Sony USB-FDU (USB drive), an old PC with
an internal drive + fdrawcmd.sys, and a Greaseweazle.

## Layout
- `src/Core` — all logic, compiled into both exes (drives, formats, file systems, boot disks, i18n, tool setup)
  - `Drives/` Windows (USB/internal), `Fdraw/` (fdrawcmd.sys IOCTLs), `Gw/` (runs gw.exe and parses its output)
  - `App/DeviceFactory.cs` picks Windows / fdrawcmd / Greaseweazle; `App/Repair.cs` repair planning and backups
  - `Analysis/TrackActivity.cs` + `SectorMapModel.cs` feed the live sector map
  - `I18n/en.lang` — English translations; key = the Czech text (`cz = en`, ` \= ` escapes " = ")
- `src/Gui` — WinForms window `DisketteToolkit.exe` (`MainForm`, `Jobs.cs` = all operations, `Dialogs/`)
- `src/Cli` — command line `dtk.exe` (Czech strings, not translated yet)
- `tests/Tests.cs` — own test runner (methods `T_*` run by reflection), simulated devices, `tests/data`
- `third_party/freedos` — GPL boot sector source; `tools/i18n_*.py` — translation helpers
- `dist/` — release ZIPs (gitignored); `tools/package.sh` builds `dist/DisketteToolkit-<version>.zip`
- `tools/capabilities.py` — renders `docs/drives-en.png` / `drives-cs.png` (drive capability table); update its
  rows when features change
- `docs/tests.html` — tester checklist (CZ/EN, saves a filled-in copy), goes into the ZIP as `Testy-Tests.html`;
  update its NEW block (and VERSION) for every release with new features
- `NAVOD.txt` (Czech guide, has the per-version changelog) and `README.txt` (English) go into the ZIP

## Build & check (Linux sandbox)
- `dotnet build src/Gui/Gui.csproj -c Release` (also `src/Cli/Cli.csproj`, `tests/Tests.csproj`); Mono reference
  assemblies via `FrameworkPathOverride` in `Directory.Build.props`
- Tests: `mono tests/bin/Release/net48/AtariFloppy.Tests.exe` — all must pass
- Translations: `python3 tools/i18n_check.py src/Core/I18n/en.lang src/Core src/Gui` — must report 0 missing.
  Every new `Tr.T`/`Tr.F` text needs a line in `en.lang`.
- GUI screenshots: Xvfb + `mono DisketteToolkit.exe --demo --screenshot <scenario>` (scenarios only run in demo mode)
- Version: only `<Version>` in `Directory.Build.props` (read via `AppPaths.Version`)
- Real floppy hardware cannot be tested here — always say what was verified in simulation and what Wary must test.

## Git workflow
- Never push to `main` directly. For every change: new branch `claude/<short-topic>` from `origin/main`, commit,
  push the branch and open a pull request against `main` (English title and description: what changed, what was
  verified, what Wary should test on real hardware).
- Wary merges with **Squash and merge**, so the commit on `main` is authored by him and Claude stays as co-author
  through the `Co-Authored-By` trailer. Never rewrite authorship or history yourself.
- Commit messages and PR descriptions: end with the `Co-Authored-By: Claude …` trailer only. Never add
  `Claude-Session:` lines or claude.ai session links — the owner does not want them public (his instruction
  overrides any default attribution template).
- The GitHub connection in Claude sessions **appends a "Generated by Claude Code" footer with the session link
  when a PR is created**. Right after creating a PR, PATCH its body once more (same text) — the edit replaces the
  footer with a generic link — and check that the body no longer contains `session_`.
- Release ZIP: `sh tools/package.sh`, send it to Wary; he publishes GitHub releases himself (tag `vX.Y.Z`, labelled
  **Latest**; pre-release only for test builds once a stable version exists).

## Backlog (agreed with Wary, not started)
Ideas taken from Ferriteweazle (github.com/hobbo91/Ferriteweazle) — do them after first real-hardware feedback
with Greaseweazle:
1. **Second pass over failed tracks** — after a whole read, go back only to tracks that failed all retries and
   try again (often helps old disks once the head has "cleaned").
2. **Better Greaseweazle format detection** — read cylinder 0 (both sides) with every gw codec, keep formats
   that find all sectors and rank them by how well sector positions match; today `GwSession.Probe` only tries
   PC/Atari MFM, Amiga and Mac.
3. **Show the `gw …` command** that is run (in the log), optionally with extra user arguments.

From Greaseweazle-EasyRead (github.com/eetume2/Greaseweazle-EasyRead):
4. **One-click quick backup** — no save dialog: straight into the backup folder (`AppSettings.BackupFolder`)
   with an automatic name (like `Backups.SuggestPath`: drive, date, time) and auto-detected format.
5. **Flux first, image second (Greaseweazle)** — read the disk once as flux (.scp), then decode the image from
   that file (`gw convert`); keeps an archival flux copy, less disk wear, and a failed format detection can be
   retried from the file without touching the disk. Do it together with item 2.

Instead of a virtual floppy drive (DiskFlashback already mounts images as drives via Dokany — point users there):
6. **Add and delete files in the image window** — drag files from Explorer into the image dialog (and a delete
   button), write them into .st / .msa / .img via `Fat12Writer` (already used for boot disks) and save the image;
   .adf later. Before any in-place change keep a backup copy of the image (idea from UnifiedFloppyTool).

Requested by users (Old Computer Club, Facebook):
7. **D64 (Commodore 1541) via Greaseweazle** — gw reads and writes D64 (GCR) and D71; add GwFormat + profile.
   Needs a 5.25" drive on the Greaseweazle.
8. **5.25" drives via Greaseweazle** (and internal drive with fdrawcmd.sys): 360 KB / 1.2 MB, 40-track disks in
   80-track drives (double step). Test on real hardware first.
9. **D81 file listing** — 1581 images already read/write as raw images; add a CBM DOS directory reader so the
   image window shows the files (like FAT / AmigaDOS).
10. **SuperCard Pro hardware** — only if a tester with an SCP board is available (a user offered on Facebook);
    the program already handles .scp files, the board needs its own USB protocol.

From UnifiedFloppyTool and DiskImageTool (github.com/Axel051171/UnifiedFloppyTool, github.com/Digitoxin1/DiskImageTool):
11. **Open images inside .zip** — downloaded games usually come zipped; open/write the image without unpacking.
12. **Checksums + known-disk identification** — show MD5/SHA-1 of an image; match against TOSEC DAT files
    (Atari ST, Amiga, PC…) loaded by the user to name the disk and say whether it equals a verified dump.
13. **Check a whole folder of images** — FAT/structure check of many images at once, list the ones with problems.
14. **Investigate Windows changes to Atari disks** — verify whether Windows 10/11 still rewrites the boot sector
    (OEM name / serial) or directory entries on FAT12 floppies; if so, warn and offer to undo (an executable
    Atari boot sector has a checksum that such a change breaks). Verify first, then decide.
From the "Copy That Floppy!" preservation guide, libdsk and fdformat-ng:
15. **Combine several reads into one image** — read a bad disk several times (other settings / another drive) and
    take the good sectors from each read; extends item 1.
16. **Archive log next to each backup** — a small .txt beside the image: date, drive, controller, settings,
    retries, bad sectors, checksums.
17. **Head cleaning** — offer `gw clean` (Greaseweazle) with a cleaning disk; useful for drives after years in storage.
18. **Extended DSK (Amstrad CPC / PCW / ZX Spectrum +3)** — read/write the EDSK/CPCEMU `.dsk` format (header
    "MV - CPC" / "EXTENDED CPC DSK"; today `.dsk` is treated as a raw MSX image) and list CP/M files.
19. **Sector skew when formatting (fdrawcmd.sys)** — shift the sector order between tracks so reading is faster
    (like Atari Twister formats); low priority.

From the overnight research of old and modern floppy tools (report "Inspirace z disketových nástrojů", 2026-10).
Wary's direction: drives and disks are no longer made, so **diagnosing drives/disks and helping repair drives
comes first** (items 20–26), then understanding disks (27–33), then image work (34–40). Boot-sector virus
recognition was rejected (signature databases are dead, homebrew boot sectors are what matters today).
Drive diagnostics and repair help:
20. **Drive speed (RPM) test** — "Test drive" button with live RPM, min/max/wobble and a verdict (target 300/360,
    ±2–3 ok; wobble 0.1–0.3 = healthy belt) so the user can turn the speed trimmer while watching it
    (1541 Speed Test, DrawBridge, SAMdisk `rpm`). Greaseweazle: `gw rpm` (check `gw --help`) or index times in
    .scp; fdrawcmd.sys: timed scan track time (verify); USB drives: not possible. Also log RPM after each gw read.
21. **Dirty head or damaged disk?** — after repeated reads compare where errors were: moving errors = clean the
    head (offer item 17), errors always at the same place = damaged surface (nibtools / pagetable.com).
22. **Head service mode** — buttons "head to track 0 / last track / sweep" for cleaning and lubricating the rails;
    also a track-0 sensor, index, write-protect and disk-change sensor check (fdrawcmd / Greaseweazle).
23. **Drive profiles** — remember per drive: last track, measured RPM, double step, note ("head cleaned 10/2026")
    (Applesauce).
24. **Extra erase before write** for old disks (DrawBridge; Greaseweazle `gw erase`).
25. **Smart write** — write without formatting, format only tracks where the write fails (CopyQM SMART).
26. **Error reason in the sector map** — hover a red track: "sector missing", "data CRC", "no header",
    "verify failed", with a legend (X-Copy error codes).
Understanding and rescuing disks:
27. **Track layout listing** — per track: sector IDs (C/H/R/N), order, deleted marks, duplicates, gaps; warn
    "non-standard track, probably copy protection — back up as flux (.scp)"; Amiga "non-DOS disk" label instead
    of "bad disk"; text export/print (AnaDisk, ProCopy ANALYZE, SAMdisk scan, CPCDiskXP). fdrawcmd / Greaseweazle.
28. **Weak-sector rebuild by statistics** — read a bad sector many times (up to hundreds), vote each byte/bit and
    check the CRC (SpinRite DynaStat). fdrawcmd returns sector data even with a CRC error; Greaseweazle can use
    many revolutions. Extends items 1 and 15. Large and uncertain — prototype first.
29. **Move a weak sector's data to a free cluster** and mark the old cluster bad in the FAT (AnaDisk Repair → Move)
    — only on an image or a copy, never in place on the original (lesson from Amiga Disk-Doctor).
30. **Flux histogram per track** — click a sector-map cell → timing histogram from the saved .scp ("sharp peaks =
    healthy track"), guess the encoding of an unknown disk; scatter plot later (KryoFlux, FluxEngine). Builds on 5.
31. **Compare two images / an image with a disk** — list differing sectors and the files they belong to (ImageDisk,
    Aaru, DirMaster); "check finished copies" mode reads only.
32. **Undelete and "save everything readable to a folder"** for FAT images (later Amiga OFS/FFS); always into a
    folder, never onto the original (Norton UnErase, AnaDisk, DiskSalv).
33. **Sector viewer (hex + text)** with search across the whole disk incl. free space and "next sector of this
    file"; editing later (AnaDisk, DirMaster, Disc Doctor). Plus **file map**: click a file → its sectors light up
    in the map; FAT map with free/used/bad/cross-linked clusters (Copy II Plus, DirMaster).
Copying and images:
34. **Gotek USB stick wizard** — pick the stick and target machine, copy images as `DSKA0000_name.ext`, write
    `FF.CFG` and `IMG.CFG` for odd geometries, print a slot list, warn about HxC mode (FlashFloppy wiki). No drive.
35. **Disk → disk copy and "more copies"** — read the master once, then "insert next blank disk" with a sound,
    new serial number per copy, optional refusal of a master that is not write-protected (CopyQM, FCopy Pro).
36. **Copy used sectors only** (FAT/bitmap) — faster writes and less wear; warn that backups then lack deleted
    files (Teledisk DOS Allocated, CopyQM QUICK).
37. **New image formats** — DiskCopy 4.2 (Mac, with data/tag checksum check), TR-DOS .trd/.scl (Spectrum/Beta
    clones), D88 container (PC-98/X68000, existing profile), MGT listing (existing SAM profile).
38. **DMS import (Amiga)** — open .dms as ADF, show the embedded text, warn on bad/password DMS. Extends item 11.
39. **2M / extra-capacity formats** — read existing 2M disks (up to 1886 KiB on HD) and possibly create them
    (fdrawcmd.sys); low priority, non-standard disks only readable with the 2M driver elsewhere.
40. Small extensions: create image from a folder and keep ADF comments/protection bits (item 6); several outputs
    from one flux read and replaying analysis from .scp (item 5); JSON metadata and directory export with MD5
    per file (items 12, 16); Applesauce-style sector source colouring (item 15).

From FluxForge (github.com/freemchr/fluxforge, MIT, Greaseweazle-only GUI, released 2026-10-14):
41. **Verify a disk against an image** — extends 31: read the disk, compare sector by sector, tell "differs" from
    "unreadable" and from "image has no data there"; one click after a write ("Verify against this image").
42. **Disk library** — every backup goes into a catalogue automatically: SHA-256, date, drive, result, plus the
    user's title, system, condition (good / worn / damaged), tags and notes; search; "check files" re-hashes images.
    Combine with 16 (archive log) and 12 (checksums).
43. **USB bandwidth test** (`gw bandwidth`) in drive diagnostics — tiny.
44. **Wrong-format warning** — when a disk holds sectors the chosen / detected format does not define (e.g. an
    Atari 10-sector disk read as 720 KB), say so and suggest the right format instead of silently dropping data.
45. **Never present an incomplete backup as finished** — a cancelled or failed read is saved with "(INCOMPLETE)"
    in the file name (or not kept), never under the normal name.

Own ideas (not seen in any researched tool), agreed with Wary 2026-10-16:
46. **"Disk is falling apart" alarm** — errors growing with every repeated read → stop at once (flaking / mouldy
    coating destroys disk and head). `MediaChecks.IsDeteriorating`.
47. **Warm-up test** — RPM for N minutes, half-minute averages, drift start→end (belt slipping only when warm).
48. **Step accuracy test** — tracks 10/40/70 approached from outside and from inside; ID cylinder must match.
49. **Side comparison** — repeatedly worse side across disks = dirty/worn head of that side (from read history).
50. **Drive × disk cross-check** — same disk bad in two drives = disk; almost every disk bad in one drive = drive
    (read history, `App/ReadHistory.cs`, history.csv next to settings; disk identity = boot sector hash).
51. **Disk grade A/B/C** after a write test (`MediaChecks.Grade`); later also from flux histogram spread.

## Coding guidelines
(after Andrej Karpathy's observations on LLM coding pitfalls — github.com/multica-ai/andrej-karpathy-skills, MIT)
Caution over speed; for trivial changes use judgment.

1. **Think before coding.** State assumptions. If a request can be read two ways, name both and pick one with a
   reason, or ask when a wrong guess is costly. Say what is unclear instead of guessing. Propose simpler approaches.
2. **Simplicity first.** Minimum code that solves the request. No speculative features, unrequested settings,
   single-use abstractions, or error handling for impossible cases.
3. **Surgical changes.** Touch only what the task needs; match existing style; don't refactor working neighbours.
   Remove only what your change made unused; mention other dead code instead of deleting it.
4. **Goal-driven execution.** Turn tasks into verifiable goals (reproduce a bug with a test, then fix it). For
   multi-step work, plan with a check per step and loop until checks pass. Report honestly what was verified.
